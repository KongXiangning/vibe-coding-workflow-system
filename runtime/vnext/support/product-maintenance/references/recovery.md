# Entry, compatibility and partial I/O

Initialize only when user authority covers creating project assets: select one
manifest path, stable project_id, current entry, managed/source/capture/excluded
paths and enabled/paused maintenance. Use templates/PRODUCT.yaml as a format,
do not install it as software over target-owned assets. capture is a candidate
location for specifically authorized original material, not blanket permission.
Apply manifest content at its read digest/null, then new authorized documents.
Missing entry or paused mode does not change existing task flow.

Read legacy v1 in place, with its own schema. To use v2 features explicitly migrate
only the relevant document/manifest in already granted scope, preserving content
and IDs. Other v1 files stay readable; unsupported versions retain raw locators.
No full-history migration or silent field aliases. Two worktrees remain separate.

On malformed individual metadata retain original bytes and report exact item,
pointer/line; read unaffected entries. On file encoding/frontmatter errors use its
raw source or ordinary authorized tools. Correct format while preserving actual
business edits, not restoring older intent. Duplicate IDs remain ambiguous; no
timestamp winner. Byte/file limits explicitly identify omitted coverage.

On conflict re-read current bytes, merge the actual affected change with user
edits, then apply with new digest. Do not use a force/approval token. Respect frozen
targets and path/symlink/permission boundaries. Each file result is independent.
Preserve captured original and any task identity even when other writes fail.
Retry only missing metadata/binding, not capture/task creation/tests. Unsaved scope
can remain explicitly deferred; no task-state repair to get permission.

Original raw material/history is target data and never installation ownership.
Software installation/upgrade only replaces its listed helper, Skill and support
assets; it does not enable maintenance or rewrite PRODUCT/user business files.

Read completeness is only the requested-path byte scope. Report omitted files,
directories/patterns and budgets separately from bad entries, partial business inventory
and delivery evidence. Preserve the junction-skip and exclude policies; do not repair
coverage by traversing all source_paths. Successful empty glob in a readable directory
is valid; explicit missing file is not. CLI exit 1 for incomplete coverage retains
the available items, not a veto on other work. Offline consumers preserve the gaps.
For a selected glob, concrete registered files inside that scope remain expected
even when missing; other registrations remain unselected and exclusions take priority.
A required static glob prefix that is a regular file is unavailable directory scope,
not a successfully enumerated empty directory. Preserve that file and report its path;
ordinary nonmatching wildcard files do not create gaps. Continue independent reads,
authorized writes and task work without scanning every source or creating a gate.

For optional-field removal use remove_fields even without metadata; merge then delete.
Deleting assessment_id removes only its display selection, not the assessment/history.
For full candidates the helper derives actual changed items and allows valid repair
of selected malformed metadata. Unchanged malformed neighbors keep exact bytes.
This includes same-value duplicate keys and anchors: whole candidates compare YAML
syntax as well as decoded values. Repair the selected syntax without cleaning unrelated
bad entries; line/index shifts alone do not make those entries selected.
Ambiguous identity/root AST needs a precisely authorized raw repair, with original
bytes retained; it does not disable the project. Item/relation deletion declarations
describe only actual removals and cannot grant permission or bypass migration/history.

After a body-boundary failure keep the original bytes, move the authorized constraint
into a ### section and reread it within the selected item. After concurrent editing
re-read the exact worktree root/project and recompute only still-needed changes;
no automatic merge of worktrees, stale replay or universal external-editor CAS claim.
Report cross-file saves individually. Existing user requests to defer maintenance or
stop are honored with saved/raw/task/binding/summary gaps separately retained.

A helper's rejected candidate never rejects the user's explicit business operation.
Within existing authority, correct format/location, preserve the old decision and
record a current explicit reversal as text when applicable; then finish the actual
save and readback. Do not ask again for an already clear field decision or require
unrelated bad entries, relation states or task management to be repaired first.
If exact-byte append is unavailable, use a precise whole candidate or an already
authorized document path; retain actual failed/unsaved results without claiming success.

For local body replacement/append, the writer supplies the Markdown separator;
closed HTML and final whitespace do not require another user decision. Verify the
new root item and retained constraints, not only saved=true. The parser may include
new EOF separators in the old body's range: original bytes and malformed YAML maps
must stay exact. Do not trim the whole document or relax root-boundary protection.
Duplicate active relation IDs remain diagnostics, not a prerequisite to changing
scope or assessment selection. Retain their values; only actual relation activation
needs the current basis, which an already explicit user reversal can supply as text.
Preserve each dismissed row separately, including different associations sharing an
ID. For an explicitly requested partial deletion, retain the other rows and declare
the actually removed ID with remove_relations; it may remain on a retained row.
For a current reversal, preserve its own prior basis and current text decision; a
different association sharing the ID does not impose its unrelated source history.
