# 有限结构维护交互材料

这些输入是隔离演练用合成材料，不是 TermLink 的真实用户要求、历史成果或已通过宿主验收。正式项目交接另保留整理前真实资料、helper 实际保存及回读结果；不能用本材料或预填 links 代替它们。

## 原始输入与两次维护

首次给宿主的材料：

> 项目结果是能保存和查询已选原文。已有原文存储与查询两项能力都属于当前范围，查询以后实施，尚无 Task。原文存储包含原文保留与来源定位；查询也使用同一来源定位能力。错误提示是查询的一个独立可核对要求。请按这些已采用层次整理现有范围，不新增设备矩阵、质量指标或其他功能。用户没有填写内部 ID。

先读项目现有定义和来源，由实际宿主判断可复用身份、父子范围、共享内容与正文细节，再用当前 helper 的 read→apply→read 保存。首次原始材料不可附上预制的完美 links 请求。宿主保留本次实际采用依据，简单示例和验收条件不机械形成新条目。

第二次给同一隔离项目的材料：

> 在已有原文存储能力下，新增一项已采用要求：保留 UTF-8 BOM 原始字节，读取时按既有原文范围处理。请在本次维护中处理相关定义与结构；不另起需求图整理，也不修改旧 Task。

从第一次实际保存结果继续 read→判断→apply→read。用实际 current_relations 和 requirement_order 说明路径、新增顺序及仍未决内容，不以格式 valid 或分类计数代替。新内容只属于隔离演练，不写入真实项目。

## 受限盘点及局部失败

另在隔离副本给宿主：

> 仅比较现有来源定位是否也适用于后续导出，不采用新归属或新功能。若材料未说明就保留问题。

查看新推断是否仍是候选／未决，不能把先前整理授权延伸到此新观点。已有明确否定的内容也不因重试复活。

局部失败演练先保存一部分，再对另一受影响文件使用旧读取摘要形成真实冲突。回读成功回执与当前字节，由宿主只补失败的关系／顺序；不重做身份、Task、捕获原文或业务动作。冲突注入和合成材料须明示，不能宣称是真实产品并发或业务验证。

## 应分别留下的证据

- 原始材料及身份／结构判断：实际依据、宿主为何选父需求、独立细项、共享身份或正文。
- 工具保存与确定性读取：请求、逐文件结果、字节摘要、实际核心关系、保留的旧顺序和新增身份。
- 仍未确定或未保存：候选、合法独立内容、正文细节、冲突与补存范围；不新增第二份当前功能清单。
- 软件来源：源码基线、正常构建资产及隔离安装字节；版本号本身不证明匹配。
- 页面消费另行验证；本材料不证明真实浏览器或 Windows 已通过。
