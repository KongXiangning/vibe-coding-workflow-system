# gstack Skill 与 Vibe Coding 方法论融合对比

本文对比 [`docs/skills.md`](../docs/skills.md) 中适合融合的 30 个 gstack skill，与当前 [`vibe-coding-methodology.md`](./vibe-coding-methodology.md) 体系中的对应位置。

## 融合程度定义

| 程度 | 含义 |
| --- | --- |
| 显式融合 | 文档中已经按该 skill 名称或生命周期角色展开。 |
| 概念融合 | 核心思想已进入方法论，但没有作为独立 skill 说明。 |
| 部分融合 | 只吸收了一部分，缺关键机制。 |
| 未融合 | 当前基本没有进入方法论。 |

## 判断

当前不是“没融合”，而是：**核心工程主链路已经融合，专题能力还没有系统融合。**

优先补的不是全部 30 个逐个展开，而是以下 5 组。

## 融合方式建议

不建议把所有 skill 都塞进 `11.3`。更好的方式是在 methodology 中新增一节：

```text
十二、gstack skill 到 Vibe Coding 治理能力的映射
```

然后按“规划、实现、审查、验证、交付、运维、安全、设计、学习”归类。这样不会把方法论文档变成 skill 说明书。
