# 合成业务原始材料：本地资料库

这是有限云端验证材料，不是 LawAgent、TermLink 或真实客户授权。

团队希望把散落的公开资料整理成可追溯的本地资料库。当前产品承诺有四块：收集和更新资料、保留资料及出处关系、把资料导入可查询库、查询并定位原文。四块均属于本次产品范围，即使查询页面排在后面也不能从当前需求去掉。

收集先接受用户指定的文本、Markdown、CSV 文件以及已取得正文的网页摘录；只给链接时应标明正文未取得。重复收集同一批相同字节不能产生重复条目；新版本保留旧版与取得时间，不能覆盖原始材料。网页动态抓取不在这一版。

保存以普通本地文件为来源记录，数据库只是可重建的查询索引。每条内容要知道原始文件和段落；后面导入和查询也必须保留这些位置。原文显示应能核对引用，不能让摘要替代原始材料。

导入约定批次要识别新增、修改和重复。格式损坏要指出具体条目或行，已完成的内容保留；修复输入后再跑不能重复写入。允许一个批次部分成功，失败不能谎称全部已入库。

查询支持关键词和资料类型筛选，并从结果打开对应原文位置。查询无结果应说明，没有足够来源不能捏造答案。团队还希望导入与查询共用相同的出处定位约定。

质量约束：原始资料不因索引失败丢失；失败位置可读；重建索引后仍能回到原文；只报告实际核对范围，不用任务数量当完成率。

未来可能支持跨设备同步，但尚未采纳。查询在一万条材料上的延迟是否满足团队使用感受尚不知道，没有明确毫秒门槛；不要自行添加 KPI。团队同意先做有限样本观察再决定是否需要优化。
