# D：测试选择效果回放（源码仓库运维材料）

此目录不随目标项目安装，不是 Test Registry、Runtime schema、Skill、发布 gate
或目标任务的新文档义务。正常项目使用既有 prepare/review/execute 入口和
`CONTEXT_API.md` 的 **Failure-oriented validation selection**。

## 公开材料与证据边界

| 材料 | 用途 | 不证明什么 |
| --- | --- | --- |
| `selection-patterns.json` | 从既往失败类型泛化的检出力说明 | 原业务源码复现、真实任务内容或实际执行结果 |
| `replay-prompts.md` | 由评估者配套授权源码的独立回放输入 | 模型已执行任务或已经提高选择准确率 |
| `reviewer-guide.md` | 整体必要性、检出力、成本与防过严评估 | 唯一测试数量、唯一 selector 或新的 gate |
| `implementation-evidence.md` | 已执行的有限源码校准及未验证边界 | 真实目标项目验收、fresh Agent 效果 |

原始用户任务及逐字摘录不在当前目录发布。泛化材料去除了原 claim、路径、
命令、来源定位/哈希、输入参数和审查原文，不再冒充可验证的原 incident。
允许分析资料不等于允许将资料公开。后续真实回放的原始输入和输出保留在
获准的私有环境；公开前单独确认范围。新提交的删除不清除旧 Git 历史、
其他 refs、缓存或已有副本，不宣称原摘录已从所有公开位置消失。

## 后续独立回放

在隔离源码上使用最终安装的 Skill 做任务准备，另起无作者上下文的会话审查。
保留模型/宿主、workflow 与业务源码版本、真实输入、读取材料、原始输出和
最终 invocation。不要向 prepare 会话提供 reviewer-guide、参考答案或历史
审查结论。已看到答案的运行只能称 informed replay；缺少源码时只做
planning-only 分析，不虚构 selector、PASS 或正式可执行 draft。

评价完整的必要验证集合，包含独立用户/策略/发布义务。比较检出能力、真实
边界和整体成本；允许有依据的合并调用，不把 focused 当唯一合格粒度。
无依据宽测仍应收窄。准备/草稿审查不执行测试；之后仅在有理由且已授权时，
对实际缺陷版本与修复版本运行所选检查。环境错误不算检出，不强制双版本测试。

一个模型的一次成功选择不证明稳定效果。仍按 A/B/C/D 后统一安装真实项目的
计划，保留少量代表性任务再判断。这里不是每个正常任务新增的文档或审批义务。
