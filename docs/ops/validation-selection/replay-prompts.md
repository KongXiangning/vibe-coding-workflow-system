# 行为回放输入

评估者提供获准使用的真实要求、匹配源码、fixture 和适用策略。公开的
`selection-patterns.json` 仅供评估者理解通用失败类型，不能替代源码或作为
prepare 会话的答案。未独立运行时不得填写执行结果或 Agent 效果评分。

## 任务准备

> 使用当前安装的 prepare-task，按提供的原始业务要求准备一个有界任务。
> 先确定相关错误的独立可观察结果，再读取候选测试的 assertion、fixture 和
> 真实生产路径。选择最少必要证据，复用/修改/新增分开判断。综合所有观察和
> 独立用户/策略/发布义务比较整体成本，不把每个 check 最窄当成唯一目标。
> 不执行测试，不新增字段、测试账本或默认 E2E。没有匹配源码时说明缺失，
> 不从报告摘要捏造正式 selector 或测试检出结果。

## 草稿审查

> 使用 review-draft 独立读取原要求、候选测试与运行配置。判断错误行为能否
> 仍然 PASS、是否遗漏真实业务边界、预期是否跟随错误实现变化。比较等价
> 验证集合，而非只比较某一个 claim 的 selector。尊重绑定的独立用户、策略
> 和发布义务；无根据的扩大仍是 finding。不执行测试，不要求 draft 已有报告。

## 防止过度测试的对照

以下是设计对照，不冒充新增真实 incident。由评估者提供对应真实上下文：

| 输入 | 评估重点 |
| --- | --- |
| 局部规则已有有效 focused check，其他边界未变 | 不自动新增同义测试、integration、E2E 或整套 suite |
| 文档说明修改，没有可执行行为 | 允许足够的静态证据，不强制单元或流程测试 |
| focused check 能证明局部 claim，但用户或发布策略另要求 package regression | 保留独立义务，不因 focused 存在而拒绝；无关 PASS 不替代 claim 证据 |
| 多个必要观察可分别选择，也可合并运行 | 比较单次批量 selector 与 target 的总成本；有充分依据时允许合并，不能仅以少一次启动扩大 |
| 无独立宽测义务，批量 selector 已同等有效且更便宜 | 要求收窄；成本措辞不能成为“顺便全跑”的通行证 |

review-change 需要真实执行目标与审查上下文。只有材料摘要时只做材料分析，
不得捏造正式 Runtime verdict。真实回放输入、输出及发布范围由评估者保管。
