# 记录存储整理：安装路由与宿主验收

本轮基于 `617bcb5540f1f8f29d2c7366ea56bda26973f004`，复用 maintain-project，
补齐既有 archive Runtime 的调用流程。未修改记录格式、归档算法、任务状态或
PRODUCT schema；未新增独立 Skill。目标项目安装更新后的产物即可发现该子流程。

## 使用方式

- “检查记录占用”：只读预览候选与实际占用、保留项，不创建任务或展示。
- “归档历史记录，保留原件”：create 后全量 verify，保留全部散文件。
- “归档并回收重复散文件”：核对恢复备份，校验成功后按明确范围 quarantine/reclaim。
- “恢复归档”：校验后恢复原路径原字节，保留同路径冲突并报告。

宿主负责理解明确请求和选择范围；资格由 Runtime 判断。不会根据年龄、关闭状态、
相似内容决定证据无用，不会因安装、升级、任务关闭或提交自动运行。固定引用减少
新捕获的约定与本历史存储整理流程各自独立。明确授权可覆盖连续操作，不逐命令重问。

## 实际验证环境与方法

Linux，Node.js v24.19.0，Bun 1.3.10，产品版本 0.24.1。五个新的原生 Agent
分别收到自然语言请求与隔离项目路径；恢复 Agent 处理正常与冲突两个项目。Agent
自行读取已安装 Skill/参考并选择命令，未得到固定请求 JSON 或预先算好的答案。
原生服务未暴露继承模型的精确 ID/build，本报告不推测该信息。场景目录有可见标签，
这是功能验收，不是盲测或所有宿主/模型的能力保证。

六个项目均无 PRODUCT manifest，fresh install 尚未 bootstrap，所以没有 AGENTS.md；
宿主从实际安装的 `.agents/skills/maintain-project/SKILL.md` 发现流程。AGENTS
的渲染路由另由 host-guidance 回归覆盖。每例有 99 个候选原件、两个任务及原始失败
执行，保护展示/恢复材料不参与回收。备份为验收前已存在的独立副本。

外置证据目录 `record-storage-workflow-20261009` 中保存原始自然请求、安装指导
SHA、实际命令/stdin/stdout/stderr/退出码、宿主最终答复，以及独立 golden 核验。
不使用私人推理或隐藏会话数据作为证据。源码及恢复包另行交付。

| 请求路径 | 实际动作与结果 | records 内容字节变化 |
| --- | --- | --- |

| 恢复 | 健康项目恢复99文件/1,011,215字节；另一项目verify因同路径冲突失败，冲突不覆盖 | 正常恢复增加1,011,215；冲突项目0 |

回收场景：311→217个records普通文件，保留212个非候选文件、3个归档文件
（136,130字节）、2个隔离/回收回执（208字节）。全部旧逻辑引用、任务身份、事实
revision、完整状态查询与受保护文件保持一致。保护文件另核对 inode、模式与mtime；
未对可继续写入的 capture inode 做归档回收。

独立备份在操作前已存在，659文件/9,151,011字节，操作后完全相同，没有新增回滚
副本。按“records + 这份保留备份”的同口径，970→876文件，11,172,705→10,297,828
内容字节；备份未被当成已删除。该统计不含外部验收日志、其他fixture、构建产物，
不宣称整台电脑净节省。创建保留原件那条路径明确报告占用增加。

故障是在宿主开始前注入的。故障场景的 task-status 已包含 TASK_LABEL_UNREADABLE；
操作前后完整查询一致，没有声称与健康seed完全相同。恢复冲突例先完整verify失败，
没有调用restore或试图修补索引；原47字节冲突内容得到保留。正常恢复后逐一核对
99个原路径文件大小/SHA、独立备份和普通 assistance read 字节。

## 回归与边界

- 全部 native assistance 回归：216/216 通过。
- 实际安装与升级回归：2/2、271 个断言通过。升级是将现有安装的
  distribution_version 改为 0.0.1 后调用 upgrade，不是实际历史发行包升级。
- host-guidance、source contract、distribution 三文件：47/48 通过；唯一失败为
  packed npm installer 的 TARGET_ROOT_DENIED，同一精确基线复现。
- Migration Pack：13/21 通过；8 个失败与精确 617bcb5 基线相同，均属于既有
  fixture/common-Git-root admission 环境问题。没有为测试放宽目标隔离。
- gen:all、validate:vnext-source、Runtime/Distribution 构建、freshness、diff 检查通过。
- 上轮全聚合的 7 个已知基线失败仍保留；本轮未将未执行的全聚合后续阶段算作通过。
  本轮执行的是与路由、安装及原生归档相关的完整套件。

本轮未在 Windows 实机运行，未修改真实 LawAgent/TermLink 记录，未推送、发布或
升级真实目标项目。恢复原件、task-view(s)、CURRENT_TASK 与非候选文件仍保留；
保留原件或隔离移动本身不代表净减量。统计为文件内容字节，不是磁盘块或 Git 历史。
