## 当前 Agent 的实际补查演练

合成项目有 26 个候选、9,855 字节目标正文、25 个绑定及不存在的供应商资料。
当前 Agent 实际使用已构建 Node helper：先读首包，再根据返回请求选择补查、作出修订并回读；没有用户追加提示指出关键页。
这是实现者参与的**非盲交互验证**，不是独立评审或跨模型统计评测。

| 场景 | 实际观察 |
| --- | --- |
| 跨范围重试修订 | 遍历 26 个候选的全部目录页；读到最后候选的“计费不得自动重试、总尝试次数最多两次”，并核对相邻义务 |
| 长正文 | 顺序读取三个正文页，读到末尾自定义约束“已提交批次禁止重放”；修订保留该限制 |
| 长数组 | 完整读取 25 个原始绑定后仅改 B-00 的覆盖说明；B-24 的 dismissed 状态和其他 24 条原记录保持 |
| 缺资料 | 沿 inventory 展开来源并实际读取，获得 SOURCE_UNAVAILABLE；修订保留供应商限流待核对，不宣称整体已完整核对 |
| 局部元数据 | 只新增合成备注 extension 并回读，没有改变业务 scope |
| 保存后呈现失败 | 已保存回执经呈现异常注入，Agent 保留成功事实并读取目标，没有重新 apply |
| 回执丢失 | 第二次写入响应对 Agent 隐藏；Agent 先核对文件 SHA、完整绑定和显式历史位置，确认已保存后没有重放 |

三次写入均在临时合成项目。事后核对：其余 25 个条目的正文和元数据未变，否定历史未变，末尾及跨候选约束保留。

以下按格式化 CLI JSON 的 UTF-8 字节计算，不是 token 数；真实 LawAgent 只读资料未修改。

首包均小于 32 KiB，默认目录及影响目录仍可继续取齐。默认单集合预算 12 KiB 为整体 envelope 及并列目录留空间，列表上限 20 条还受字节预算约束。
合成演练共 49 次读取、3 次写入，完整 CLI 回执累计 413,821 字节。该演练刻意逐条核对相邻义务并重复做故障回读，不能拿首包缩小比例当作整个任务的节省比例。
完整所需正文、必要诊断和原件仍有不可省略的成本；宿主也可批量选择已明确需要的条目，减少重复往返。

Runtime 仍完整解析原范围，不新增索引缓存或模型摘要。分页完成不证明 AI 理解了业务，也无法保证任意模型不会漏读；本轮证明的是接口可完整取得、代表性交互实际补查，以及原业务判定／写入路径保持。

## 整体复核

复核发现并修正：后续候选页需保留目录摘要；原始 impact 字段查询不能混入目录包装；大型 inventory 不能隐藏状态；评估 applicability 必须可见；推断关系不能标作已声明父项；微小显示预算不能吞掉所选身份；异常 Unicode 原值不能因分页被替换。
补充了相应行为断言，按 simplify 指导整理新增呈现函数，没有重构业务模块。

最终未发现剩余的业务判定或写入逻辑变更。没有新增迁移、审批、阅读令牌或 Task 状态机，也没有修改 TraceLens。
