| 场景 | 本轮演算结果 |

| 同一需求支持两个目标 | R-IMPORT／G-DEMO／FULL 与 R-IMPORT／G-LIVE／RECOVERABLE 分别选 A-DEMO 的 satisfied、A-LIVE 的 partially-satisfied；不能跨目标套用。 |
| 同范围不同对象 | 工作副本 sample-copy-a@sample-baseline 与 sample-release-0 分别选择 satisfied、not-satisfied；另一个 commit／副本没有适用报告。 |

| 初始登记、追加、重排、未登记 | 单一 project.requirement_order；批次尾部追加、明确采用才重排，目标筛选保留相对位置；R-UNORDERED 独立可见。 |
| 缺少／错误／冲突总目标 | 保留项目定位与可读条目；不按 current、文件顺序或图算法选根。 |
| 报告冲突与替代 | 多个未替代报告待核对，标签相同也不合并；同定位 supersedes 才移入旧报告历史。非法跨范围边只使声明方选择冲突，被指向选择不降级；环只影响其候选。 |
| 定义变化与反证 | 需求变化为 definition-changed；仅目标正文改变为 goal-definition-changed；当前范围变动为 scope-definition-changed／scope-not-current。两份依据未知及 pending_sources 分别保留，旧成果仍可读。 |
| 四值与整体未知 | partial 需明确成果和未满足部分；其他范围未知时 undetermined 但保留局部成果；目标层独立报告，不汇总任务数量。 |
| 旧 v2 报告与空资料 | 旧 assessment_id 保留导航，PASS 不转换为满足；完整 v3 新报告可按原算法核对旧 requirement，goal 必须提供当前声明与依据；元数据缺失只影响展示，Task 不受阻。 |
