## 用户基线及判断方式

用户本轮明确：不允许因为维护流程阻塞而否决已明确的添加需求、拆分需求、设计等操作。
Agent 应在既有授权内调整候选格式、定位、记录和恢复方法，实际完成目标。真正尚未明确的
业务取舍才提问；已明确的字段选择或改变原决定无需重复审批。具体 I/O 或保存失败仍如实
保留，不能据此宣称操作已经完成，也不能扩大为整个项目的执行禁令。

这符合现有 requirements P09/P10/P11、VPM-04/11/13/14/22，document-contract 第 8 节，
maintain-project 主 Skill 及 recovery/update references，以及 vNext 的非阻塞 assistance。
helper 对错误候选的具体诊断不是否决用户目标。当前用户明确重新关联本身可写成 text 来源，
无需额外外部材料、审批标记或新的状态。保留旧决定与新决定即可。
