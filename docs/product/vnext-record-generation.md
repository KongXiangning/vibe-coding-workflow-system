# vNext：生成端减量，不删独立事实

实施基线：4266b895d83907c17a59e0449033db3cc93b3f90。
用户明确要求减少重复累计捕获、事件内部报告双份及仅revision变化引起的展示副本；
不同运行的结果、失败、用户决定、数据库前后状态仍完整保留。旧事件与既有归档不改写。

## 1. 明确固定引用与本轮输出

新增record/task的evidence_refs输入：指向已保存的不可变证据ref及SHA256（或已知CAS摘要）。
服务完整核验存在性、字节摘要与可选大小，保留本轮事件对旧材料的关联，不再读取原live
来源路径，也不写一份新blob。引用失败明确留在附件清单，原始请求先保存，不自动改成抓取
当前文件。mutable业务路径须先snapshot再引用，避免把路径名当成历史身份。

files仍表示调用者明确要求捕获的本轮原字节，即使与旧材料相似、是累计文件，也不能自动
省略、截取或用更旧摘要替换。Skill指导选择固定旧材料引用＋本轮必要输出，不再惯例性
重捕获完整task-status或累计材料集合。不同运行、失败日志、用户决定、数据库before/after
不以相似度、前缀关系或已提交为去重依据；完全相同字节的CAS复用沿用原契约。

## 2. 同事件内的request/data可靠复用

新生成的task事件可以使用版本化v2编码：完整原请求保留一次，data中的重复长值/子树
通过受限、确定性的同事件request指针引用。先核验wire payload摘要，再解码给现有
reducer、重放和查询，保持完整逻辑请求身份；不引入另一份正文指针文件或新reducer。
对小值和不能变小的记录保留v1；原始record输入不擅自改写。

旧事件字节、摘要和路径不变，解码支持v1。未知版本、非法指针、请求摘要不符和过量展开
显式诊断。原始read默认仍返回可按文件SHA校验的存储字节；显式logical-task-event读取
提供完整解码正文和wire/logical身份，不混用两个摘要。events-only find仍能找到正文，
因为正文完整保留在事件request中。checkpoint对存储格式和逻辑引用闭包均作核验。

## 3. 事实revision与展示语义分离

source_revision/view_revision仍由完整事实计算，task-view.json和task-status保持当前真实
状态。CURRENT_TASK v2使用display_revision描述稳定展示内容，不携带随无关事实变化的
source/view revision；文中明确通过task-status/context读取当前事实。

task-views/<display_revision>.md保存确定性展示基线。只有语义展示内容改变才发布新的
CURRENT_TASK和相应必要副本；当前字节必须先与真实发布基线核对。v1完整baseline仍可识别，
语义不变时不为了升级格式制造新副本；真实语义变化时才升级。未知、缺基线或用户编辑的
展示保持drift，不猜测可覆盖。正常查询只读。

实际发布仍保护并发路径保存及旧inode延迟写入，display-capture原件不回收。不删除历史
task-views来掩盖增长，不建立逐revision的新增指针文件，不把view状态变成开发准入。
checkpoint必须识别新旧真实发布基线，并继续保护外部编辑与恢复原件。

## 验证边界

- 固定引用＋新run输出与显式累计捕获两类均有行为测试，不能只验证文档字符串
- 原始/解码正文、请求冲突/幂等、旧事件、错误与未知版本、归档恢复和Git离线clone完整性
- 纯事实revision变化新增0个展示/恢复副本；语义变化、外部编辑、旧句柄、并发与中断回退
- 精确测量不同记录类别的文件数和字节；真实样本原树只读，隔离副本/合成场景验证
- 原生Node与构建Bun边界不变；生成产物从源码重建，真实安装升级及关联回归实际执行

没有推送、发布、真实项目安装或清理授权；本轮只做源码、隔离验证及本地可恢复交付。

## 并发基线增强

本轮并发探针独立复现了4266的短时STORE_BUSY：一个并发CLI任务可能未保存或暂未编号。
仅增加获取既有存储锁前最多2秒的单调时钟等待，重试未成功的link，不重跑回调或业务操作。
owner变更和EEXIST→ENOENT竞争共用同一期限，不消耗64层恢复链计数。仍保留超时
STORE_BUSY、原互斥、显式死owner恢复和“不按年龄偷锁”；不是锁体系重构。
