# vNext：管理能力与流程准入解耦

基线：`4fdc7af22d2136a9a18df1555dd2d99d8b430bcc`（0.22.1）。
本次是用户明确授权的职责变更，不是增加一个 force 开关，也不是严格模式的恢复补丁。
本文件与新版 WORKFLOW_PROTOCOL 取代旧文档中“必须先取得 Runtime 准入才能开发”的要求。

## 1. 目标与边界

保留证据、测试、任务和知识的记录、历史、定位及读取能力；拆掉这些管理能力与当前任务
状态、证据适用性、审查资格、预算和恢复手续的强制依赖。Skill 负责按用户意图开展工作，
Runtime 负责提供服务。用户未授权的外部影响不能因为服务返回成功就变成已授权。

旧证据仍是旧版本的事实；它可以不适用于当前结论，但不能因此禁止读取历史、保存新事实
或继续独立的已授权工作。磁盘写入失败必须如实报告，而不是伪造成功；失败局限于这一次
服务调用，不产生禁止开发的状态，也不要求先维修工作流软件。

## 2. 当前实现中需要切断的依赖

0.22.1 的现有路径在管理操作中组合了 CURRENT_TASK 解析、活动步骤、计划版本、预检、
审查结果及完成资格。证据对象层已经保存内容寻址 blob，但上层沿用判断还检查当前上下文
和引用路径内容；存在保存的历史原文，并不等于它能通过当前资格检查。

因此不采用“把所有 fail 改为 warning”：后续事务仍依赖那些状态，直接返回 success 会
伪造保存/完成。也不继续补用户豁免类型和恢复状态。将这些旧事务保留为可选专用工具，
从默认 Skill 的执行路径中移除。

## 3. 实施结构

新增永久安装的原生 Node 服务 `runtime/vnext/support/assistance.mjs`，仅依赖 Node
内置模块，不导入 kernel、CURRENT_TASK parser、Task Store qualification 或 run-entry。
这不是待执行的改代码脚本；它本身就是运行时服务，安装后直接执行，无额外编译依赖。

| 命令 | 作用 | 不要求的前置条件 |
| --- | --- | --- |
| context | 提供当前/历史文件及新记录的导航 | 活跃任务合法、schema 升级、审查通过 |
| record | 原始观察先持久化，再尝试附件快照/关联 | 计划版本新鲜、ID 完整、结果通过 |
| snapshot | 显式文件的内容寻址快照或既有历史对象 | 当前 slot 合格、preflight 回执 |
| read | 分页读固定 blob 或具体文件 | 当前版本等于报告版本、活跃状态 |
| find | 按字面内容分页查报告、测试、任务及旧历史 | 当前任务解析、沿用资格、有效 cursor revision |

新数据追加到 `.workflow-system/records`，旧 Task Store、历史对象和文档不改写。
这是管理事实的追加日志，不另建一套 verified 状态机，也不尝试双写严格任务内核。
原始输入保留在事件中，失败/缺失附件留在附属记录；计划、结果、审查和用户关闭各自记录。
旧 CURRENT_TASK 是历史投影，不再是读取和新写入的必经入口。后续计划/处置显式关联旧记录，
不得把旧投影状态当作新记录已经获得或尚未获得的执行权限。需要旧结构对账时单独进行，
对账没有完成不阻碍开发。

写入先形成完整临时文件，再通过不覆盖的发布操作提交。相同幂等输入复用原记录；相同 key
但不同输入作为冲突新观察保留，并关联旧记录，不覆盖、更不把新说法升级为事实认证。
服务不执行命令或测试，因此重放记录不会重跑业务操作。

固定历史内容按摘要读取，新路径内容不冒充旧摘要。对象不存在/损坏时报告缺失，不能靠 hash
重建内容。当前适用性默认 not-evaluated；服务成功只说明这次管理操作的结果。

软件升级同时移除对当前任务 active/closed tuple 的检查；否则损坏的旧任务连辅助工具都
无法装入。保留安装文件归属、漂移、锁、冻结目标和原子发布检查；这些是安装自身的
实际 I/O 条件，不是对用户开发的批准。旧任务和新 journal 不属于软件替换目标。

## 4. Skill 与协议切换

全部公开 Skill 改用 assistance 作为默认记录/读取工具，不再强制 validate/preflight/
run-entry/waiver/claim migration/完成资格来开始或结束普通工作。保留实际用户范围、
只读约束、明确后果确认、自查与自审区分及 minimum-sufficient evidence。

execute 记录真实工作，默认不登记正式审查；用户已有明确组合授权时按相应方法完成多个
动作，不要求重发入口命令。close 可以记录未完成终止，不隐瞒失败，不自动 rollback、
commit 或部署。测试计划/测试结果继续关联和检索，但不要求每次微调新增测试或跑全套。

SOURCE_CONTRACT/RUNTIME_CONTRACT 中的旧能力、事务及其约束作为兼容接口清单保留，
不再被解释成日常入口的强制前置条件。源码验证器保留入口/mode/元数据/权限结构与路由
名称检查，取消要求 Skill 必须声明/运行旧 run-entry 恢复驱动的文案门槛。

## 5. 保留能力与明确不做的事

不删除现有 kernel、Task Store、文档查找、测试/证据历史、原子写入、安装升级能力。
不更改旧证据 PASS/failed，不擦除 finding，不伪造用户授权，不迁移或重置真实任务。
不自动把新观察写入旧严格投影，不靠 silent best-effort 返回虚假的完整归档/验证成功。

新记录服务不代替代码沙箱、权限系统或发布系统。业务本身确实不可执行、用户授权不清、
真实外部依赖不可用仍需处理；这些不能与 Runtime 偏好的状态流程混为一谈。

## 6. 验收与交付

只用少量有独立价值的行为场景检查：损坏/旧状态不阻止记录读取；固定旧报告可读；
附件缺失不丢原始事实；相同与冲突重放保留事实；分页与大文件；安装位置直接运行及并发写入。
不为文案变更新增字符串测试，不自动跑 test:workflow-all。

本次不发布版本、不部署或修改 LawAgent 等业务项目。原生服务与模板/打包源码已写入本地源码交付包，GitHub 上传未成功；
完整分发构建和目标项目安装仍须使用原发行流程。不得将仅复制文件的 CLI 冒烟测试说成完整
npm 安装/升级验收。具体已执行检查与剩余限制见 docs/ops/vnext-assistance-validation.md。
