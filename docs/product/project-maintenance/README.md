## 1. 要达到的结果

契约修订 0.3.1 已补齐五项审查意见：当前范围及目标依据、可信 Runtime 登记、旧需求引用、跨范围替代隔离、文件／内存快照。0.3.2 按[后续审查原则](../../ops/TraceLens与vNext_目标需求管理及可视化完整方案.md#711-后续契约与-ai-指导审查原则2026-10-11-补充)仅澄清同定位的不完整报告与已替代异常报告；保留目标整体摘要的保守取舍，VN-02 规则不变。修订与一致性复核见上述验收记录；这些仍是 VN-03／TL-01 等后续包的实现输入，不能据文档精确性保证 AI 判断正确。

为个人开发者增加一个 `maintain-project` 能力：持续维护当前目标、完整已知需求、设计、分阶段实施计划、任务关联、交付依据，以及用户主动提交的思考资料。TraceLens 只读这些标准文档和已安装 Runtime 的任务查询，按业务显示全貌，不调用模型、不重算 journal、不写回产品或任务。

实施可以预先安排全部已知工作，也可以无总体 plan 持续选取近期工作，或保留总体方向只细化近期。按相关目标／需求、设计、交付与前提核对后，在授权内直接准备既有 vNext task；需要项目计划时再使用 plan／工作项。三种方式不是 Runtime 模式。

开发纠偏：外部观察／缺陷 → 影响核对 → 修复或其他新增工作 → 原需求与历史交付；结果回到交付摘要。

没有 plan 的持续选取、简单需求和明确修复都可直接 prepare-task；没有计划、格式错误、关联未完成、历史任务已关闭，都不新增开工、提交、结束或停止门槛。维护失败必须如实报告，不能假装成功。

## 3. 可直接交给实施 Agent 的目标

```text
阅读 docs/product/project-maintenance/README.md，并按其顺序读取需求、契约、实现方案和验收文档。
在当前 vibe-coding-workflow-system 中实现完整的 maintain-project 首版，覆盖 VPM-01～25；不要停在规范、脚手架、Schema 或演示页面。
先核对本地 HEAD 与文档勘察基线的差异，复用当前主线接口；保留用户改动。按实际需要划分工作并准备近期 task，简单工作不强制先建项目计划。
产品文档读写与现有任务状态服务分离；任务身份和真实任务操作复用现有 assistance。不能手改 CURRENT_TASK、复制 reducer 或用文档缺口阻止正常工作。
完成标准包含已安装目录中的可运行 helper、可发现的 Skill、参考资料／模板／契约、任务关联与非阻塞场景验证，以及不安装 Runtime 的离线读取样例。
TraceLens 源码不属于本仓库的默认写入范围。没有获得其仓库授权时，交付消费者契约和样例，明确未完成真实前端集成，不虚报页面通过。
按风险使用最小充分验证；区分源码、分发、安装和真实 Agent 行为。保留已有失败与未核对范围，不为每个文案添加测试。
未经另行授权不发布包、不推送业务项目、不部署。达到验收后报告实现范围、实际检查、安装使用方式和剩余限制；不要扩展无关平台能力。
```

上段是交给后续实施 Agent 的任务目标，不是本次设计提交已经执行这些操作的声明；实际写入、提交和外部操作仍服从实施会话授权。
