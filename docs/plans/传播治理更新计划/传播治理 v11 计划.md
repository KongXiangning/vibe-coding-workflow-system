# 传播治理 v11 计划（隐式共享符号自动升级 Gate 闭环）

## Summary

聚焦修复一个高优先级缺口：`IMPLICIT_SHARED_OBJECT_UNPROTECTED` 已在 `v9` 引入，但“发现了共享对象却未登记”后的处理仍未进入正式 gate 闭环。

`v11` 只处理这一件事，把“隐式共享符号自动升级”从建议升级为可验证结果：

- 明确 `IMPLICIT_SHARED_OBJECT_UNPROTECTED` 的默认 blocker level
- 定义 merge / ship gate 映射
- 定义“自动升级建议被忽略时何时阻断”
- 把 candidate 状态、回写要求、忽略后果接入 `ContractCompatibilityResult`
- 更新 schema、protocol 和 tests，使其成为正式验证入口

## Key Changes

### 1. 隐式共享对象的 required-when 语义

当传播分析发现某个未登记对象满足共享性阈值时，必须触发自动升级流程。

默认触发条件：

- direct consumers `>= 3`：生成 `🟡 candidate`
- direct consumers `>= 5`：生成 `🔒 candidate`
- direct consumers `>= 3` 且命中跨边界 / critical path / locked-hit chain：直接生成 `🔒 candidate`

形式化结构：

```yaml
implicit_shared_object_detection:
  object_path: <string>
  object_kind: <symbol|api|dto-field|entity-field|ui-anchor|layout-container>
  direct_consumers: <number>
  cross_boundary: <true|false>
  critical_path_hit: <true|false>
  proposed_contract_state: <extend-only-candidate|locked-candidate>
  writeback_required: <true|false>
```

规则：

- 触发后必须二选一：
  - 回写到 `CONTRACTS.md`
  - 输出标准 blocker 结果并停止继续修改
- 不允许存在“检测到了共享对象，但既不回写、也不阻断”的中间状态

### 2. 新增协议级 gate 映射

把 `IMPLICIT_SHARED_OBJECT_UNPROTECTED` 变成标准错误结果。

默认 gate：

- `IMPLICIT_SHARED_OBJECT_UNPROTECTED` → `blocks-merge`

ship/deploy 升级规则：

- 若该对象已命中兼容窗口、迁移窗口、release baseline 或生产关键路径，ship gate 升级为 `blocks-ship`

正式映射表：

| Condition | Error Code | Default Blocker Level | Rule |
|---|---|---|---|
| 检测到共享对象，应升级但未回写 `CONTRACTS.md` | `IMPLICIT_SHARED_OBJECT_UNPROTECTED` | `blocks-merge` | 不允许继续直接修改该对象 |
| 检测到 `🔒 candidate`，但仍按未受保护对象继续原地修改 | `IMPLICIT_SHARED_OBJECT_UNPROTECTED` | `blocks-merge` | 直接阻断 merge |
| 检测到共享对象且命中 release / ship critical path，仍未回写或未停机 | `IMPLICIT_SHARED_OBJECT_UNPROTECTED` | `blocks-ship` | 不得 ship |

### 3. candidate 到正式锁定状态的收敛规则

补上 `candidate` 状态的正式闭环。

默认规则：

- `extend-only-candidate`
  - 在当前任务内视同 `🟡`
  - 若继续推进实现，必须回写到 `CONTRACTS.md`
- `locked-candidate`
  - 在当前任务内视同 `🔒`
  - 未回写前也不得直接修改旧语义

回写时机：

- 若任务继续进入实现步骤，回写是强制动作
- 若任务停止在分析阶段，可暂不回写，但必须输出 blocker 结果或待确认项

优先级规则：

- 显式 `🔒` / `🟡` 永远高于 candidate
- candidate 与旧 registry 冲突时，默认按更严格的一侧执行
- candidate 不是 advisory tag，而是当前任务内立即生效的临时保护级别

### 4. 与现有 result contract 的集成

把自动升级闭环接入 `ContractCompatibilityResult`。

结果示意：

```yaml
contract_compatibility_result:
  error_code: IMPLICIT_SHARED_OBJECT_UNPROTECTED
  object_path: <string>
  severity: error
  default_blocker_level: blocks-merge
  evidence:
    - <EvidenceRecord ref or summary>
  strategy_origin:
    over_limit_policy_branch: none
    divergence_state: none
  branch_gate_mapping:
    merge_gate: blocks-merge
    ship_gate: blocks-ship
    rationale: shared object was discovered but not promoted into an effective protected contract state
  suggested_resolution: promote the object into CONTRACTS.md or stop modifying it in the current task
```

统一规则：

- `IMPLICIT_SHARED_OBJECT_UNPROTECTED` 必须包含：
  - `object_path`
  - `direct_consumers`
  - `proposed_contract_state`
  - `writeback_required`
  - `suggested_resolution`
- “自动建议升级”不能只写在任务备注里，必须能映射到正式结果

## Test Plan

必须覆盖以下场景：

- 未登记对象 direct consumers `>= 3`，生成 `extend-only-candidate`
- 未登记对象 direct consumers `>= 5`，生成 `locked-candidate`
- 命中 candidate 但未回写 `CONTRACTS.md` 仍继续修改，产出 `IMPLICIT_SHARED_OBJECT_UNPROTECTED`
- candidate 与旧 registry 冲突时，按更严格保护级别执行
- merge 阶段默认 `blocks-merge`
- ship critical path 上升级为 `blocks-ship`
- `ContractCompatibilityResult` 中该错误必须包含：
  - `error_code`
  - `default_blocker_level`
  - `branch_gate_mapping`
  - `suggested_resolution`

## Assumptions

- 这一轮只聚焦 `IMPLICIT_SHARED_OBJECT_UNPROTECTED` 的 gate 闭环，不同时扩展 `v9` 其他新增结构
- 下一版文件命名默认延续版本序列，可作为 `v11`
- candidate 在当前任务内是有效保护状态，不是仅供参考的提示
- 发现共享对象后，系统必须“回写或阻断”，不存在第三种继续实现的状态
