# 传播治理 v13 计划（主线回归补回版：补齐 v12 遗漏的 schema 与规则）

## Summary

`v13` 是对 `v12` 的最小范围补回版，只修复 `v12` 在主线整合时相对 `v9 / v10 / v11` 丢失的 3 组硬规则，不再扩展新主题：

- 补回 `migration_plan_requirement` 的触发语义，以及 `StagedMigrationPlan` 的最小完整性规则
- 补回 `implicit_shared_object_detection` 的正式 schema，与“回写或阻断”的结构化协议
- 补回 `EntityMutationChecklist`、`RegistryFreshnessReport` 的具体规则，以及 `INCOMPATIBLE_MUTATION_CONFLICT`

`v13` 的目标不是替换 `v12` 的方向，而是把 `v12` 恢复成真正“不丢失 `v9 / v10 / v11` 关键规则”的主线版本。

## Key Changes

### 1. 补回 `migration_plan_requirement` 与 `StagedMigrationPlan` 完整性规则

在 `v12` 已保留错误码和 blocker 语义的基础上，补回 `v10` 的触发和完整性细则。

补回正式结构：

```yaml
migration_plan_requirement:
  required: <true|false>
  trigger_reason:
    - <recommend_task_split|multi_phase_compat|dual_field_transition|v2_cutover|ui_anchor_transition|cross_boundary_migration>
```

补回触发规则：

- `required=true` 且任务继续实现时，没有 `StagedMigrationPlan` 就直接失败
- `required=true` 但选择“仅输出分析不实现”时，可不提供完整迁移计划，但必须明确停机

补回 `StagedMigrationPlan` 的最小完整性要求：

- `migration_id`
- 至少 2 个 phase
- 每个 phase 必须包含：
  - `objective`
  - `preconditions`
  - `allowed_mutations`
  - `runtime_state`
  - `verification`
  - `exit_criteria`
- 明确 phase dependencies
- 明确哪一阶段开始引入兼容层，哪一阶段允许移除旧行为

补回完整性校验：

- 没有 `runtime_state` 视为 `MIGRATION_RUNTIME_STATE_UNDECLARED`
- phase 顺序依赖无法形成有效 DAG，视为 `MIGRATION_PHASE_ORDER_INVALID`
- phase 数量不足、字段缺失、没有 verification / exit criteria，视为 `MIGRATION_PLAN_INCOMPLETE`

### 2. 补回 `implicit_shared_object_detection` schema 与“回写或阻断”协议

在 `v12` 已保留 candidate 阈值和 gate 的基础上，补回 `v11` 的结构化检测记录。

补回正式结构：

```yaml
implicit_shared_object_detection:
  object_path: <string>
  object_kind: <symbol|api|dto-field|entity-field|ui-anchor|layout-container>
  direct_consumers: <number>
  cross_boundary: <true|false>
  critical_path_hit: <true|false>
  proposed_contract_state: <extend-only-candidate|locked-candidate>
  writeback_required: <true|false>
```

补回协议规则：

- 触发后必须二选一：
  - 回写到 `CONTRACTS.md`
  - 输出标准 blocker 结果并停止继续修改
- 不允许存在“检测到了共享对象，但既不回写、也不阻断”的中间状态

同时把这条规则写回 schema / protocol / tests，而不只是保留在 candidate 章节的自然语言说明里。

### 3. 补回 `EntityMutationChecklist` 的逐类覆盖模板

`v12` 已把 `EntityMutationChecklist` 放回 `Public Interfaces`，但没有保留 `v9` 的分类覆盖面。`v13` 要补回固定模板。

补回覆盖类别：

- 定义处
- 构造点 / factory
- 写入点 / repository / ORM
- 读取点 / query / selector
- 映射层 / mapper / adapter
- 序列化 / 反序列化 / validator
- API / DTO / event
- 测试 / fixture / mock / snapshot
- 前端消费
  - hook / store / page / widget / form / table / detail view
- 文档 / 示例

补回推荐结构：

```yaml
entity_mutation_checklist:
  entity_name: <string>
  categories:
    definition: <covered|gap>
    construction: <covered|gap>
    writes: <covered|gap>
    reads: <covered|gap>
    mapping: <covered|gap>
    serialization: <covered|gap>
    api_dto_event: <covered|gap>
    tests: <covered|gap>
    frontend_consumers: <covered|gap>
    docs_examples: <covered|gap>
  unresolved_categories:
    - <string>
```

要求：

- `EntityMutationChecklist` 不是结构名占位，而是实体变更任务中的正式检查模板
- 若存在 `gap`，必须进入 `unresolved_categories` 或 blocker 判断

### 4. 补回 `RegistryFreshnessReport` 的鲜度规则

`v12` 已声明 `RegistryFreshnessReport` 为公开结构，但没有带回 `v9` 的鲜度判断规则。

补回推荐结构：

```yaml
registry_freshness_report:
  object_path: <string>
  registry_consumers: <number>
  discovered_consumers: <number>
  freshness: <fresh|stale|unknown>
  divergence_summary: <string>
```

补回默认规则：

- registry 与 evidence 发现结果不一致时，默认按 discovered union 扩展
- 若 registry stale 且命中 `🔒` 对象，默认 `blocks-merge`

这条规则要进入：

- `CONTRACTS.md` / `CURRENT_TASK.md` 相关 schema
- `WORKFLOW_PROTOCOL.md` 的 validation / compatibility 说明
- 测试用例

### 5. 补回 `INCOMPATIBLE_MUTATION_CONFLICT`

`v12` 在主线错误清单里遗漏了 `v9` 的实体不可兼容冲突错误码。`v13` 要把它补回统一错误面。

补回标准错误码：

- `INCOMPATIBLE_MUTATION_CONFLICT`

触发条件：

- 实体 / DTO / event / API field 变更命中了某个 `🔒` consumer
- 且没有兼容层、双字段、v2、mapper、adapter 等可行过渡路径

默认 gate：

- merge 阶段：`blocks-merge`
- 若该冲突直接影响 release / ship compatibility baseline，则在 ship gate 升级为 `blocks-ship`

并要求该错误同样纳入 `ContractCompatibilityResult`，继续包含：

- `error_code`
- `object_path`
- `severity`
- `default_blocker_level`
- `evidence`
- `strategy_origin`
- `branch_gate_mapping`
- `suggested_resolution`

## Test Plan

必须覆盖以下场景：

- `v13` 保留 `v12` 的主线整合内容，同时补回 `migration_plan_requirement` 的 `required / trigger_reason`
- `recommend_task_split` 场景中：
  - `required=true` 且继续实现但无计划，产出 `MIGRATION_PLAN_REQUIRED_BUT_MISSING`
  - analysis-only 时允许无完整计划，但必须明确停机
- `StagedMigrationPlan` 缺少 `runtime_state`，产出 `MIGRATION_RUNTIME_STATE_UNDECLARED`
- `StagedMigrationPlan` phase 不足、字段缺失、缺少 verification / exit criteria，产出 `MIGRATION_PLAN_INCOMPLETE`
- `implicit_shared_object_detection` 必须包含 `object_kind`、`direct_consumers`、`cross_boundary`、`critical_path_hit`、`proposed_contract_state`、`writeback_required`
- 命中隐式共享对象后，既未回写也未阻断时，不允许通过验证
- `EntityMutationChecklist` 必须按分类覆盖；存在 `gap` 时必须进入 unresolved 或 blocker 处理
- registry 与 evidence 结果不一致时，按 discovered union 扩展
- registry stale 且命中 `🔒` 对象时，触发 blocker
- 实体 / DTO / event / API field 命中 `🔒` consumer 且无兼容路径时，产出 `INCOMPATIBLE_MUTATION_CONFLICT`

## Assumptions

- `v13` 是对 `v12` 的最小补回版，不重新打开新的治理主题
- `v12` 的 candidate、linked regression、layout / behavior gate、migration blocker 主方向保持不变
- 这一轮只补回 `v12` 相对 `v9 / v10 / v11` 丢失的 schema 和规则，不额外扩展新的结构或错误码
