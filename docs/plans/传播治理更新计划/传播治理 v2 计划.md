# 传播治理 v2 计划（补齐 UI / 符号 / API / 实体传播闭环）

## Summary

把现有体系从“文件级边界 + 改完检查”升级为“传播级治理 + 改前分析”。  
仍复用现有文档结构，但正式补入 5 个硬规则：

- 统一锁定对象命名语法
- UI 锚点 / 关系 / 扩展区契约
- 影响集合强制计算清单
- 不确定即停机
- 兼容层生命周期治理

这套规则统一适用于：

- UI 页面与组件
- 同文件多符号场景
- 实体 / DTO / schema / event 变更
- 前后端多消费方共享 API

## Key Changes

### 1. 锁定对象命名语法

在 `CONTRACTS.md`、`CURRENT_TASK.md`、协议与模板里正式定义锁定对象语法，禁止再用模糊描述替代。

推荐统一语法：

- 文件：`src/foo/bar.ts`
- 符号：`src/foo/bar.ts::getOrderSummary`
- 参数：`src/foo/bar.ts::getOrderSummary(status)`
- 深层参数语义：`src/foo/bar.ts::getOrderSummary(options.includeDraft)`
- 返回字段：`src/foo/bar.ts::getOrderSummary@return.total`
- DTO 字段：`src/foo/bar.ts::OrderDTO.status`
- 事件字段：`src/events/order.ts::OrderCreatedEvent.total`
- API 契约：`api::GET /orders`
- API 请求字段：`api::GET /orders?status`
- API 返回字段：`api::GET /orders@return.items[].status`
- UI 区域：`ui::OrdersPage/HeaderActions`
- UI 锚点：`ui::OrdersPage/HeaderActions.SearchBar`
- UI 关系：`ui::OrdersPage/HeaderActions.SearchBar -> PrimaryCTA [left-of/right-of/aligned-with]`

语义规则：

- 所有 `🔒`、`🟡`、`🟢` 项都必须可落到这种路径
- 未能命名到具体对象的锁定项，视为不合格契约
- 任务中的影响集合、冲突集合、回归矩阵都必须引用这些路径，不允许只写“订单页相关逻辑”

### 2. UI 契约升级为可校验对象

在 `CONTRACTS.md` 的现有结构内补强 UI 契约，不新增一级文档，但在接口契约与变更规则里明确以下对象：

- 页面区域
- 组件锚点
- 元素位置关系
- 关键交互状态
- 禁止改变的视觉语义
- 允许扩展区 / 禁止扰动区 / 完全冻结区

固定表达能力必须支持：

- 左右关系
- 上下关系
- 顺序关系
- 对齐关系
- 占位 / 伸缩关系
- 层级关系
- 可见性关系
- 尺寸关系

示例对象：

- `ui::OrdersPage/HeaderActions`
  - `按钮顺序固定`
- `ui::OrdersPage/HeaderActions.SearchBar`
  - `左对齐固定`
  - `不可因新增元素改为右对齐`
- `ui::OrdersPage/PrimaryCTA`
  - `始终位于首屏右上`
- `ui::OrdersPage/List.EmptyState`
  - `empty/loading/error 三态布局固定`
- `ui::OrdersPage/OrderDrawer`
  - `宽度固定规则`
  - `层级不可低于 modal`
- `ui::OrdersPage/StickyFilters`
  - `sticky 区域固定`

大页面强制声明三类区域：

- `允许扩展区`
- `只能扩展不能重排区`
- `完全冻结区`

### 3. 参数 / 字段级冻结规则

在 `CONTRACTS.md` 和 `BASELINES.md` 明确参数与字段的变更规则，避免“函数没改名但默认行为变了”绕过治理。

必须定义：

- 新增参数是否允许
- 是否只允许新增可选参数
- 默认值变化是否视为破坏性变更
- 参数名冻结还是语义冻结
- 返回字段是否允许新增
- 返回字段是否允许删除
- 返回字段是否允许改语义
- DTO / event 字段是否允许重命名
- 字段重命名是否必须走双字段或映射过渡

默认规则：

- 已锁定函数仅允许新增可选参数，不允许修改既有参数语义与默认行为
- 已锁定 API 默认允许新增向后兼容字段，不允许删除旧字段或改变旧字段语义
- 字段重命名默认禁止原地替换，优先双字段 / adapter / mapper / v2
- 默认值变化按“行为变化”处理，不得视为无害调整

### 4. 影响集合强制计算清单

把“影响集合”从抽象概念提升为固定清单。  
凡命中共享接口、共享符号、实体结构、DTO/API 字段、关键 UI 的任务，必须逐项计算：

- 定义处
- 导出处
- 直接调用方
- 间接调用链
- 入参构造点
- 返回值消费点
- 映射 / 序列化 / 反序列化 / 校验层
- 前端 consumer
  - page / hook / store / selector / widget / form / table / detail view
- 测试 / mock / fixture / snapshot
- 文档 / 示例
- 锁定对象命中情况
- 冲突处理策略
- 回归验证对象

规则：

- `CURRENT_TASK.md` 必须在触发传播条件时记录：
  - `变更起点`
  - `影响集合`
  - `必改集合`
  - `冲突集合`
  - `兼容策略`
  - `回归矩阵`
- 未完成这张清单，不进入实现步骤

### 5. 不确定即停机

把“不确定时停机”写成协议级硬规则，而不是建议。

必须停机的条件：

- 影响集合无法明确枚举
- 消费方列表不完整
- 迁移条件不明确
- 锁定对象命中后未定义兼容策略
- UI 锚点边界不明确
- 无法确认旧语义是否会被改变
- 实体 / DTO / API 字段的传播范围存在未确认消费者

停机后的允许输出仅限：

- 未确认传播点清单
- 已确认冲突点清单
- 建议兼容策略
- 需要补充的搜索 / 验证入口

禁止在上述条件下继续实现旧语义破坏性变更。

### 6. API 作为跨边界共享契约 + consumer registry

把 API 从“后端接口”正式纠正为“跨边界共享契约”。

每个稳定 API 至少记录：

- Provider
- Consumers
- Locked request fields
- Locked response fields
- Optional additive fields
- Non-breakable semantics
- Deprecation window
- Removal precondition
- Default compatibility strategy

建议记录形式落在 `CONTRACTS.md`，而不是只放任务里。  
`CURRENT_TASK.md` 只引用被命中的 API consumer registry 条目。

示例：

- `api::GET /orders`
  - Provider: `src/api/orders/getOrders`
  - Consumers:
    - `ui::OrdersPage`
    - `src/hooks/useOrders.ts::useOrders`
    - `src/store/ordersStore.ts::fetchOrders`
    - `ui::OrderSummaryWidget`
  - Locked request fields:
    - `status`
    - `page`
  - Locked response fields:
    - `items[].id`
    - `items[].status`
    - `summary.total`
  - Optional additive fields:
    - `items[].tags`
  - Deprecation window:
    - `v1 -> v2`
  - Removal precondition:
    - `all listed consumers migrated`

### 7. 兼容层生命周期

把兼容层治理正式放进 `BASELINES.md` 的 `## 兼容性基线`。

必须定义：

- 何时允许引入兼容层
- 何时允许移除旧层
- 旧字段淘汰前提
- 多消费方全部迁移完成的判定标准
- 版本窗口 / 迁移窗口
- 迁移证据要求

默认规则：

- 命中锁定符号 / 锁定字段 / 多消费方 API 时，优先兼容层
- 兼容层包括：
  - adapter
  - wrapper
  - mapper
  - decorator / AA
  - dual field
  - v2 API
- 未满足 “所有已登记 consumers 完成迁移 + 回归通过 + 淘汰条件满足” 前，不允许移除旧行为

## Test Plan

必须覆盖以下场景：

- UI 锚点被错误重排时，任务包或契约检查能明确指出冲突
- 新增重元素时，只允许进入允许扩展区，不允许扰动冻结区
- 同文件 `A/B/C/Z` 多符号共享时，`A` 被锁定且 `Z` 走 `AA`
- 实体 `P` 字段变更时，影响集合必须覆盖后端、前端、测试、映射层
- API 被多个前端 consumer 复用时，不允许直接删旧字段
- 命中传播条件但未列全影响集合时，触发停机
- 未迁移完全部 consumer 时，不允许移除兼容层
- 普通小改动未命中传播条件时，仍可维持轻流程

验证入口至少包括：

- `bun run test:workflow-docs`
- 相关 workflow runtime / validation tests
- freshness checks for generated docs
