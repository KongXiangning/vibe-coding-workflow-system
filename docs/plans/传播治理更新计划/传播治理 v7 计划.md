# 传播治理 v7 计划（继承声明 + 策略分支 Gate 化）

## Summary

在 v6 基础上补两个正式缺口：

- 明确声明 `V4/V5` 的公开结构、生命周期规则、blocker mapping 仍全部保留，`V6` 仅增不减
- 把 `V6` 新增的裁决分支正式映射到标准错误码与 gate，避免只有策略、没有执行阻断

同时补一条更宽的继承规则：

- `V1/V2/V3` 的核心规范仍然有效，除非后续版本显式 supersede
- `V4/V5` 的公开结构和兼容性报告格式在 `V6/V7` 中继续生效，不得隐式弱化

## Inheritance Rules

### 1. 显式继承声明

新版必须在 Summary 或 Public Contracts 段落明确写入：

`V7 retains all public structures, lifecycle rules, and blocker-mapped compatibility reporting introduced in V4 and V5, and keeps V1-V3 normative rules unless explicitly superseded. V7 adds only inheritance clarification and strategy-branch-to-gate mapping on top of V6.`

等价中文表述也必须存在，避免实现者只读中文段落时遗漏。

### 2. 继承矩阵

必须显式列出以下内容仍然有效：

- 来自 `V1`
  - 变更起点 / 影响集合 / 必改集合 / 冲突集合 / 兼容策略 / 回归矩阵
  - 条件触发传播分析
  - 跨边界 API 契约
- 来自 `V2`
  - 锁定对象命名语法
  - UI 锚点 / 关系 / 冻结区 / 扩展区
  - 参数 / 字段冻结规则
  - consumer registry
  - 不确定即停机
  - 兼容层生命周期
- 来自 `V3`
  - 发现机制要求
  - machine-checkable UI anchor
  - 错误类型体系
- 来自 `V4`
  - `EvidenceRecord`
  - `UIAnchorReplacement`
  - `ContractCompatibilityResult`
  - blocker-mapped compatibility reporting
- 来自 `V5`
  - `EvidenceAggregation`
  - `ComplexityAssessment`
  - confidence aggregation
  - unresolved gap escalation
- 来自 `V6`
  - `over_limit_policy`
  - `evidence_diff_threshold`
  - graded forced strategies
  - complexity/evidence 联动升级

规则：

- 后续版本默认只能 `additive extend`
- 若要移除、替换、降级任一结构，必须显式标注 `superseded`
- 不允许因为新计划重点变化，就把旧结构视为“背景材料而非约束”

## Strategy Branch To Gate Mapping

### 1. V6 分支必须 Gate 化

把以下策略分支正式映射到标准 gate 与错误码：

| Strategy / Condition | Default Error Code | Default Blocker Level | Rule |
|---|---|---|---|
| `hard_stop` | `IMPACT_HARD_STOP_REQUIRED` | `blocks-merge` | 一旦命中，不得进入实现 |
| `enforce_adapter_boundary` but no valid adapter / facade / mapper boundary artifact | `COMPAT_ADAPTER_BOUNDARY_MISSING` | `blocks-merge` | 不允许继续跨边界直改 |
| `enforce_compat_layer` but no valid wrapper / v2 / dual-field / mapper strategy | `COMPAT_LAYER_REQUIRED_BUT_MISSING` | `blocks-merge` | 不允许继续原地破坏旧语义 |
| `recommend_task_split` ignored and current task scope expanded | `IMPACT_TASK_SPLIT_IGNORED` | `blocks-merge` | 不能继续在当前任务里扩大传播面 |
| `significant_divergence` on locked/shared/API/UI frozen targets | `IMPACT_SIGNIFICANT_DIVERGENCE_BLOCKING` | `blocks-merge` | 证据冲突未消解前不得实现 |
| `within-limit` but unresolved locked-hit gap remains | `IMPACT_LOCKED_HIT_GAP_UNRESOLVED` | `blocks-merge` | 即使未超限，也不能带 gap 修改锁定对象 |
| `COMPAT_WINDOW_VIOLATION` at ship/deploy gate | `COMPAT_WINDOW_VIOLATION` | `blocks-ship` | 迁移窗口未满足时不得 ship |
| `COMPAT_REMOVAL_PRECONDITION_UNMET` at ship/deploy gate | `COMPAT_REMOVAL_PRECONDITION_UNMET` | `blocks-ship` | 移除前提未满足时不得 ship |

### 2. Gate 映射原则

新增统一规则：

- `strategy branch` 必须能映射到 `ContractCompatibilityResult`
- 不允许存在“有策略结论但没有 error_code / blocker level”的状态
- 对 `🔒` 对象命中的分支，不得降级为 `warning-only`
- `within-limit` 不等于可继续实现，只要仍有 `locked-hit unresolved gap`，仍阻断 merge
- `ship/deploy` gate 继续沿用 `V4` 的升级原则：
  - merge 阶段默认 `blocks-merge`
  - 涉及迁移窗口 / removal precondition 的错误在 ship 阶段可升级为 `blocks-ship`

### 3. 推荐新增错误码

在现有错误码集上增加：

- `IMPACT_HARD_STOP_REQUIRED`
- `COMPAT_ADAPTER_BOUNDARY_MISSING`
- `COMPAT_LAYER_REQUIRED_BUT_MISSING`
- `IMPACT_TASK_SPLIT_IGNORED`
- `IMPACT_SIGNIFICANT_DIVERGENCE_BLOCKING`
- `IMPACT_LOCKED_HIT_GAP_UNRESOLVED`

这些错误码属于 additive extension，不替代 V3/V4 已有错误码。

## Public Interfaces / Contracts

### 1. 保留的公开结构

必须显式声明以下公开结构全部保留：

- `EvidenceRecord`
- `UIAnchorReplacement`
- `ContractCompatibilityResult`
- `EvidenceAggregation`
- `ComplexityAssessment`

以及继续保留：

- blocker-mapped compatibility reporting
- UI anchor replacement lifecycle
- evidence confidence / unresolved gap handling
- compatibility window / removal precondition semantics

### 2. V7 新增结构字段

本轮不新增全新顶级结构，只补两个字段族：

- `ContractCompatibilityResult.strategy_origin`
- `ContractCompatibilityResult.branch_gate_mapping`

推荐形式：

```yaml
contract_compatibility_result:
  error_code: <string>
  object_path: <string>
  severity: <warning|error|critical>
  default_blocker_level: <warning-only|blocks-merge|blocks-ship>
  strategy_origin:
    over_limit_policy_branch: <recommend_task_split|enforce_compat_layer|enforce_adapter_boundary|hard_stop|none>
    divergence_state: <none|significant_divergence|locked_hit_gap>
  suggested_resolution: <string>
```

## Assumptions

- `V7` 是对 `V6` 的 additive clarification，不替代 `V4/V5` 结构，也不废止 `V1-V3` 规则
- 所有公开结构继续有效，除非未来显式写出 superseded 关系
- 所有强策略分支必须 gate 化，不允许只停留在“建议动作”
- `locked-hit unresolved gap` 的阻断优先级高于“within-limit”
- 本轮仍优先补协议、schema、模板、结果 contract，不要求立即实现完整自动裁决器
- 这轮继续属于协议与文档 contract 扩展，建议协议版本从 `0.7.0` 提升到 `0.8.0`
