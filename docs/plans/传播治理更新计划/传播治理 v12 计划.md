# 传播治理 v12 计划（主线整合：公开结构补全 + Candidate 收敛 + 链式回归 Gate 化）

## Summary

产出一个新的主线版本 `v12`，把三类内容统一收束回同一份正式计划：

- 回收 `v10` 的 `StagedMigrationPlan` 强制阻断化
- 回收 `v11` 的隐式共享对象 candidate / gate 闭环
- 修复 `v9` 剩余 4 个中风险缺口：
  - 新结构未进入统一 `Public Interfaces / Contracts`
  - candidate 到正式锁定状态缺少收敛协议
  - 链式回归停机规则过于抽象
  - `LayoutContract` / `BehaviorContract` 缺少标准错误码和 gate 映射

`v12` 目标是恢复“主线版本自洽”：实现者只看 `v12` 就能获得完整 contract 面、标准错误码、默认 blocker level、以及写回/停机规则，不再需要同时拼接 `v9 + v10 + v11`。

## Key Changes

### 1. 统一补全 Public Interfaces / Contracts

在 `v12` 的 `Public Interfaces / Contracts` 章节中，显式列出并保留以下公开结构：

- 继承自 `v4 / v5`
  - `EvidenceRecord`
  - `UIAnchorReplacement`
  - `ContractCompatibilityResult`
  - `EvidenceAggregation`
  - `ComplexityAssessment`
- 来自 `v9` 主线新增
  - `MutationEligibilityAssessment`
  - `EntityMutationChecklist`
  - `LayoutContract`
  - `RegistryFreshnessReport`
  - `LinkedRegressionRecord`
  - `BehaviorContract`
  - `StagedMigrationPlan`
- 来自 `v10 / v11` 的补强约束
  - `migration_plan_requirement`
  - `implicit_shared_object_detection`

同时明确：

- `v12` retains all public structures from `v4-v11` unless explicitly superseded
- 新增结构一旦被 schema / protocol / tests 引用，必须同步进入 `Public Interfaces` 清单
- 后续版本禁止再次出现“文中使用了结构，但 contract 面未声明”的情况

### 2. 把 candidate 收敛协议正式写死并回收 `v11`

把 `v11` 中已经形成的 candidate / gate 闭环回收进 `v12` 主线，并补齐收敛时序。

默认检测阈值：

- direct consumers `>= 3` -> `extend-only-candidate`
- direct consumers `>= 5` -> `locked-candidate`
- direct consumers `>= 3` 且命中 `cross-boundary / critical path / locked-hit chain` -> `locked-candidate`

收敛规则：

- `extend-only-candidate`
  - 在当前任务内按真实 `🟡` 处理
  - 若继续推进实现，必须回写到 `CONTRACTS.md`
- `locked-candidate`
  - 在当前任务内按真实 `🔒` 处理
  - 不允许继续直接修改，除非先回写到 `CONTRACTS.md` 或走兼容层 / 停机
- 显式 `🔒` / `🟡` 永远高于 candidate
- candidate 与旧 registry 冲突时，按更严格的一侧执行
- candidate 不是 advisory tag，而是当前任务内立即生效的临时保护级别

标准错误和 gate：

- `IMPLICIT_SHARED_OBJECT_UNPROTECTED`
  - 默认 `blocks-merge`
  - 命中 release / ship critical path 且仍未回写或未停机时升级为 `blocks-ship`

强制闭环：

- 发现共享对象后，implementer 只能二选一：
  - 回写 `CONTRACTS.md`
  - 输出标准 blocker 结果并停止对该对象的直接修改

### 3. 把链式回归变成可校验协议

把 `LinkedRegressionRecord` 从“原则”补成“带窗口、带阈值、带 gate”的规则。

新增标准结构字段：

- `regression_chain_id`
- `window_scope`
- `window_size`
- `count_basis`
- `linked_components`
- `escalation`

默认统计规则：

- `window_scope`: 当前任务 + 最近 1 个直接前序修复任务
- `window_size`: 2 个连续修复单元
- `count_basis`: 以 `fix chain / task` 为单位，不按单条 commit 计
- 默认不跨独立会话追溯；仅当同一 `regression_chain_id` 被显式延续时才跨会话累计

默认触发条件：

- 若关联回归在同一 `regression_chain_id` 下连续出现 `>= 2` 次
- 且触发对象与上一轮修复对象存在共享依赖、共享 consumer、共享 layout region、共享 behavior contract、或同一迁移链路

则产出：

- `LINKED_REGRESSION_EARLY_STOP`
  - 默认 `blocks-merge`

若命中 release / ship critical path，可升级为：

- `blocks-ship`

同时明确：

- “连续”按 `fix chain / task` 统计，不按文件编辑次数统计
- 未绑定到同一 `regression_chain_id` 的普通新 bug 不算链式回归
- 命中链式回归后，默认要求停机分析，不允许继续按普通 bug 线性修补

### 4. 为 Layout / Behavior Contract 增加标准错误码和 gate

把 `LayoutContract` 和 `BehaviorContract` 从“可表达对象”推进到统一裁决层。

新增标准错误码：

- `LAYOUT_CONTRACT_BREAK`
- `BEHAVIOR_CONTRACT_BREAK`

默认 blocker level：

- `LAYOUT_CONTRACT_BREAK` -> `blocks-merge`
- `BEHAVIOR_CONTRACT_BREAK` -> `blocks-merge`

ship / deploy 升级规则：

- 若命中 frozen UI region、locked anchor relation、critical interaction path、或 release-critical behavior contract
- 且未通过兼容层或替代迁移
- 可升级为 `blocks-ship`

裁决对象：

- `LayoutContract`
  - 父容器布局模型
  - 关键 CSS 属性值
  - 关键 region / anchor 的位置、对齐、伸缩、层级、可见性关系
- `BehaviorContract`
  - 排序语义
  - 默认分支
  - 参数默认值语义
  - 条件行为断言
  - API / function 的关键运行时行为

统一要求：

- 只要 tests / validation 命中了 layout break 或 behavior break，就必须产出正式 `ContractCompatibilityResult`
- 不允许只写成口头描述或人工备注

### 5. 把 `v10` 的 StagedMigrationPlan 正式并入主线

把 `v10` 的迁移计划阻断化直接并入 `v12` 主线，而不再作为孤立补丁阅读。

保留并主线化：

- `MIGRATION_PLAN_REQUIRED_BUT_MISSING`
- `MIGRATION_PLAN_INCOMPLETE`
- `MIGRATION_PHASE_ORDER_INVALID`
- `MIGRATION_RUNTIME_STATE_UNDECLARED`

默认 gate：

- merge 阶段默认 `blocks-merge`
- ship 阶段在兼容窗口相关场景可升级为 `blocks-ship`

同时明确：

- `recommend_task_split` 若继续推进，必须转化为有效 `StagedMigrationPlan`
- “判为不完整”必须对应正式错误码，不能停留在任务备注

## Public Errors / Gate Mapping To Add

`v12` 需要把以下错误纳入统一 error-code 清单与 `ContractCompatibilityResult` 映射：

- `IMPLICIT_SHARED_OBJECT_UNPROTECTED` -> `blocks-merge`，critical ship path 升级 `blocks-ship`
- `MIGRATION_PLAN_REQUIRED_BUT_MISSING` -> `blocks-merge`
- `MIGRATION_PLAN_INCOMPLETE` -> `blocks-merge`
- `MIGRATION_PHASE_ORDER_INVALID` -> `blocks-merge`
- `MIGRATION_RUNTIME_STATE_UNDECLARED` -> `blocks-merge`
- `LINKED_REGRESSION_EARLY_STOP` -> `blocks-merge`
- `LAYOUT_CONTRACT_BREAK` -> `blocks-merge`
- `BEHAVIOR_CONTRACT_BREAK` -> `blocks-merge`

所有这些结果必须继续包含：

- `error_code`
- `object_path`
- `severity`
- `default_blocker_level`
- `evidence`
- `strategy_origin`
- `branch_gate_mapping`
- `suggested_resolution`

## Test Plan

必须覆盖以下场景：

- `v12` 的 `Public Interfaces` 明确列出 `MutationEligibilityAssessment`、`EntityMutationChecklist`、`LayoutContract`、`RegistryFreshnessReport`、`LinkedRegressionRecord`、`BehaviorContract`、`StagedMigrationPlan`
- 未登记对象命中 shared threshold 后生成 candidate，并在当前任务内立即按 `🟡 / 🔒` 生效
- candidate 未回写 `CONTRACTS.md` 且继续修改时，产出 `IMPLICIT_SHARED_OBJECT_UNPROTECTED`
- candidate 与显式锁定项冲突时，按更严格级别执行
- 同一 `regression_chain_id` 下连续 2 个 fix task 触发关联回归时，产出 `LINKED_REGRESSION_EARLY_STOP`
- 不同 regression chain 的普通新 bug 不误判为链式回归
- layout contract 被破坏时，产出 `LAYOUT_CONTRACT_BREAK`
- behavior contract 被破坏时，产出 `BEHAVIOR_CONTRACT_BREAK`
- `recommend_task_split` 继续推进但无迁移计划时，产出 `MIGRATION_PLAN_REQUIRED_BUT_MISSING`
- migration plan 不完整、phase 非法、runtime state 缺失时分别产出对应错误
- 上述错误结果都必须带 `branch_gate_mapping`，merge 默认为 `blocks-merge`，需要时 ship 升级为 `blocks-ship`

验证入口至少包括：

- `bun run test:workflow-docs`
- 相关 protocol / validation tests
- generated docs freshness checks

## Assumptions

- 下一版采用 `v12` 命名，作为新的主线整合版本
- `v10` 和 `v11` 的内容不丢失，而是被并入 `v12`
- 这一轮目标是“主线自洽”，不是继续产出独立补丁版
- 链式回归默认统计窗口采用“当前任务 + 最近 1 个直接前序修复任务”；若后续需要跨更长窗口，再单独扩展
- `LayoutContract` / `BehaviorContract` 默认与其他 `🔒` 契约一样，先按 `blocks-merge` 处理，再按关键路径升级
