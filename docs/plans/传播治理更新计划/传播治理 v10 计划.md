# 传播治理 v10 计划（StagedMigrationPlan 强制阻断化）

## Summary

聚焦修复一个高优先级缺口：`StagedMigrationPlan` 已被引入，但“缺失时如何阻断”还停留在文档要求，没有进入协议级错误码与 gate。

`v10` 只处理这一件事，把“大变更必须拆阶段”从建议升级为可验证结果：

- 新增标准错误码：`MIGRATION_PLAN_REQUIRED_BUT_MISSING`
- 明确默认 blocker level：`blocks-merge`
- 定义触发条件：哪些场景必须产出 `StagedMigrationPlan`
- 把缺失 / 不完整 / 非法继续推进都接入 `ContractCompatibilityResult`
- 更新 schema、protocol 和 tests，使其成为正式验证入口而不是注释性要求

## Key Changes

### 1. 何时强制要求 `StagedMigrationPlan`

把 `StagedMigrationPlan` 的必填条件写死。默认只要满足以下任一条件，就必须提供迁移计划：

- `over_limit_policy` 结果为 `recommend_task_split`
- 当前任务继续推进一个原本应拆分的大变更
- 变更涉及跨阶段兼容窗口、双字段、v2 API、adapter 过渡、UI anchor 迁移中的多阶段切换
- 变更无法在单个原子任务中完成且系统必须经历“半迁移状态”

形式化触发字段：

```yaml
migration_plan_requirement:
  required: <true|false>
  trigger_reason:
    - <recommend_task_split|multi_phase_compat|dual_field_transition|v2_cutover|ui_anchor_transition|cross_boundary_migration>
```

规则：

- `required=true` 且任务继续实现时，没有 `StagedMigrationPlan` 就直接失败
- `required=true` 但选择“仅输出分析不实现”时，可不提供完整迁移计划，但必须明确停机

### 2. 新增协议级错误码与 gate

新增标准错误码：

- `MIGRATION_PLAN_REQUIRED_BUT_MISSING`
- `MIGRATION_PLAN_INCOMPLETE`
- `MIGRATION_PHASE_ORDER_INVALID`
- `MIGRATION_RUNTIME_STATE_UNDECLARED`

默认 gate：

- `MIGRATION_PLAN_REQUIRED_BUT_MISSING` → `blocks-merge`
- `MIGRATION_PLAN_INCOMPLETE` → `blocks-merge`
- `MIGRATION_PHASE_ORDER_INVALID` → `blocks-merge`
- `MIGRATION_RUNTIME_STATE_UNDECLARED` → `blocks-merge`

ship/deploy 升级规则：

- 若迁移窗口已进入发布阶段，且仍缺计划或阶段定义错误，可在 ship gate 升级为 `blocks-ship`
- 默认 merge 阶段先阻断，不等到 ship 才发现

### 3. `StagedMigrationPlan` 的最小完整性要求

把现有结构从“有个模板”升级为“有完整性校验”。

计划至少必须包含：

- `migration_id`
- 至少 2 个 phase
- 每个 phase 的：
  - `objective`
  - `preconditions`
  - `allowed_mutations`
  - `runtime_state`
  - `verification`
  - `exit_criteria`
- 明确 phase dependencies
- 明确哪一阶段开始引入兼容层，哪一阶段允许移除旧行为

新增完整性规则：

- 没有 `runtime_state` 视为 `MIGRATION_RUNTIME_STATE_UNDECLARED`
- phase 存在但顺序依赖无法形成有效 DAG，视为 `MIGRATION_PHASE_ORDER_INVALID`
- phase 数量不足、字段缺失、没有 verification/exit criteria，视为 `MIGRATION_PLAN_INCOMPLETE`

### 4. 与现有 gate / result contract 的集成

把迁移计划要求接入现有 `ContractCompatibilityResult`，而不是单独放在任务说明中。

新增结果示意：

```yaml
contract_compatibility_result:
  error_code: MIGRATION_PLAN_REQUIRED_BUT_MISSING
  object_path: migration::<migration_id|task_id>
  severity: error
  default_blocker_level: blocks-merge
  evidence:
    - <EvidenceRecord ref or summary>
  strategy_origin:
    over_limit_policy_branch: recommend_task_split
    divergence_state: none
  branch_gate_mapping:
    merge_gate: blocks-merge
    ship_gate: blocks-ship
    rationale: split-task migration was required but no staged migration plan was present
  suggested_resolution: add a valid StagedMigrationPlan before continuing implementation
```

统一规则：

- `recommend_task_split` 不再只是 advisory
- 一旦继续推进当前任务，必须转化为：
  - 有效 `StagedMigrationPlan`
  - 或标准 blocker 结果
- “判为不完整”必须映射成正式错误结果，不允许只写在任务备注里

## Test Plan

必须覆盖以下场景：

- `recommend_task_split` 命中且继续推进，但没有 `StagedMigrationPlan`，产出 `MIGRATION_PLAN_REQUIRED_BUT_MISSING`
- 有 `StagedMigrationPlan` 但只有 1 个 phase，产出 `MIGRATION_PLAN_INCOMPLETE`
- phase 缺少 `runtime_state`，产出 `MIGRATION_RUNTIME_STATE_UNDECLARED`
- phase 依赖顺序非法，产出 `MIGRATION_PHASE_ORDER_INVALID`
- migration plan 合法时，不再触发上述 blocker
- merge 阶段默认 `blocks-merge`，ship 阶段可升级为 `blocks-ship`
- `ContractCompatibilityResult` 中 migration-plan 相关错误必须包含：
  - `error_code`
  - `default_blocker_level`
  - `branch_gate_mapping`
  - `suggested_resolution`

## Assumptions

- 这一轮只聚焦 `StagedMigrationPlan` 的强制阻断化，不同时扩展其他 `v9` 新结构
- 下一版文件命名默认延续版本序列，可作为 `v10`
- 默认策略是：只要继续推进一个被判定应拆分的大变更，就必须提交计划；否则阻断 merge
- `StagedMigrationPlan` 的缺失与不完整先按 `blocks-merge` 处理，发布阶段再按既有兼容性规则升级
