# 传播治理 v14 计划（主线整合完整版）

## Summary

`v14` 是新的主线整合版本，直接吸收并统一 `v12 + v13` 的内容，不再要求实现者同时拼接多个补丁版计划阅读。

本版目标：

- 保留 `v4-v13` 已确立的公开结构、生命周期规则、blocker-mapped compatibility reporting
- 统一 `Public Interfaces / Contracts`
- 统一 candidate 收敛、链式回归、layout / behavior contract、migration blocker、entity / registry 规则
- 让实现者只看 `v14` 就能获得完整 contract 面、错误码、默认 gate、schema 结构和测试要求

## Public Interfaces / Contracts

`v14` retains all public structures from `v4-v13` unless explicitly superseded。

统一公开结构如下：

- 来自 `v4 / v5`
  - `EvidenceRecord`
  - `UIAnchorReplacement`
  - `ContractCompatibilityResult`
  - `EvidenceAggregation`
  - `ComplexityAssessment`
- 来自主线传播治理
  - `MutationEligibilityAssessment`
  - `EntityMutationChecklist`
  - `LayoutContract`
  - `RegistryFreshnessReport`
  - `LinkedRegressionRecord`
  - `BehaviorContract`
  - `StagedMigrationPlan`
- 来自 focused patch 并入主线
  - `migration_plan_requirement`
  - `implicit_shared_object_detection`

规则：

- 新增结构一旦被 schema / protocol / tests 引用，必须同步进入 `Public Interfaces / Contracts`
- 后续版本默认只能 `additive extend`
- 若要移除、替换、降级任一结构，必须显式标注 `superseded`

`ContractCompatibilityResult` 继续保留并强制包含：

- `error_code`
- `object_path`
- `severity`
- `default_blocker_level`
- `evidence`
- `strategy_origin`
- `branch_gate_mapping`
- `suggested_resolution`

推荐结构：

```yaml
contract_compatibility_result:
  error_code: <string>
  object_path: <string>
  severity: <warning|error|critical>
  default_blocker_level: <warning-only|blocks-merge|blocks-ship>
  evidence:
    - <EvidenceRecord ref or summary>
  strategy_origin:
    over_limit_policy_branch: <recommend_task_split|enforce_compat_layer|enforce_adapter_boundary|hard_stop|none>
    divergence_state: <none|significant_divergence|locked_hit_gap>
  branch_gate_mapping:
    merge_gate: <warning-only|blocks-merge>
    ship_gate: <warning-only|blocks-merge|blocks-ship>
    rationale: <string>
  suggested_resolution: <string>
```

## Key Changes

### 1. Candidate 收敛与隐式共享对象治理

默认检测阈值：

- direct consumers `>= 3` -> `extend-only-candidate`
- direct consumers `>= 5` -> `locked-candidate`
- direct consumers `>= 3` 且命中 `cross-boundary / critical path / locked-hit chain` -> `locked-candidate`

`implicit_shared_object_detection` 正式结构：

```yaml
implicit_shared_object_detection:
  object_path: <string>
  object_kind: <symbol|api|dto-field|entity-field|ui-anchor|layout-container>
  direct_consumers: <number>
  cross_boundary: <true|false>
  critical_path_hit: <true|false>
  proposed_contract_state: <extend-only-candidate|locked-candidate>
  writeback_required: <true|false>
```

收敛规则：

- `extend-only-candidate`
  - 在当前任务内按真实 `🟡` 处理
  - 若继续推进实现，必须回写到 `CONTRACTS.md`
- `locked-candidate`
  - 在当前任务内按真实 `🔒` 处理
  - 未回写前不得直接修改旧语义
- 显式 `🔒` / `🟡` 永远高于 candidate
- candidate 与旧 registry 冲突时，按更严格的一侧执行
- candidate 不是 advisory tag，而是当前任务内立即生效的临时保护级别

强制闭环：

- 检测到共享对象后，必须二选一：
  - 回写到 `CONTRACTS.md`
  - 输出 blocker 结果并停止继续修改
- 不允许存在“检测到了共享对象，但既不回写、也不阻断”的中间状态

标准错误：

- `IMPLICIT_SHARED_OBJECT_UNPROTECTED`
  - 默认 `blocks-merge`
  - 命中 release / ship critical path 且仍未回写或未停机时升级为 `blocks-ship`

### 2. 链式回归协议

`LinkedRegressionRecord` 从原则升级为可校验协议。

标准字段：

- `regression_chain_id`
- `window_scope`
- `window_size`
- `count_basis`
- `linked_components`
- `escalation`

默认统计规则：

- `window_scope`: 当前任务 + 最近 1 个直接前序修复任务
- `window_size`: 2 个连续修复单元
- `count_basis`: 以 `fix chain / task` 为单位，不按单条 commit 计
- 默认不跨独立会话追溯；仅当同一 `regression_chain_id` 被显式延续时才跨会话累计

默认触发条件：

- 同一 `regression_chain_id` 下连续出现 `>= 2` 次关联回归
- 且触发对象与上一轮修复对象存在共享依赖、共享 consumer、共享 layout region、共享 behavior contract、或同一迁移链路

标准错误：

- `LINKED_REGRESSION_EARLY_STOP`
  - 默认 `blocks-merge`
  - 命中 release / ship critical path 时可升级为 `blocks-ship`

### 3. Layout / Behavior Contract 正式 gate 化

`LayoutContract` 裁决对象：

- 父容器布局模型
- 关键 CSS 属性值
- 关键 region / anchor 的位置、对齐、伸缩、层级、可见性关系

`BehaviorContract` 裁决对象：

- 排序语义
- 默认分支
- 参数默认值语义
- 条件行为断言
- API / function 的关键运行时行为

标准错误：

- `LAYOUT_CONTRACT_BREAK` -> `blocks-merge`
- `BEHAVIOR_CONTRACT_BREAK` -> `blocks-merge`

ship 升级规则：

- 命中 frozen UI region、locked anchor relation、critical interaction path、或 release-critical behavior contract
- 且未通过兼容层或替代迁移
- 可升级为 `blocks-ship`

统一要求：

- 只要 tests / validation 命中了 layout break 或 behavior break，就必须产出正式 `ContractCompatibilityResult`

### 4. Migration 计划强制阻断化

`migration_plan_requirement` 正式结构：

```yaml
migration_plan_requirement:
  required: <true|false>
  trigger_reason:
    - <recommend_task_split|multi_phase_compat|dual_field_transition|v2_cutover|ui_anchor_transition|cross_boundary_migration>
```

触发规则：

- `required=true` 且任务继续实现时，没有 `StagedMigrationPlan` 就直接失败
- `required=true` 但选择“仅输出分析不实现”时，可不提供完整迁移计划，但必须明确停机

`StagedMigrationPlan` 最小完整性要求：

- `migration_id`
- 至少 2 个 phase
- 每个 phase 必须包含：
  - `objective`
  - `preconditions`
  - `allowed_mutations`
  - `runtime_state`
  - `verification`
  - `exit_criteria`
- 明确 phase dependencies
- 明确哪一阶段开始引入兼容层，哪一阶段允许移除旧行为

完整性校验：

- 没有 `runtime_state` -> `MIGRATION_RUNTIME_STATE_UNDECLARED`
- phase 顺序依赖无法形成有效 DAG -> `MIGRATION_PHASE_ORDER_INVALID`
- phase 数量不足、字段缺失、没有 verification / exit criteria -> `MIGRATION_PLAN_INCOMPLETE`

标准错误：

- `MIGRATION_PLAN_REQUIRED_BUT_MISSING` -> `blocks-merge`
- `MIGRATION_PLAN_INCOMPLETE` -> `blocks-merge`
- `MIGRATION_PHASE_ORDER_INVALID` -> `blocks-merge`
- `MIGRATION_RUNTIME_STATE_UNDECLARED` -> `blocks-merge`

ship 升级规则：

- 迁移窗口相关场景可升级为 `blocks-ship`

### 5. 实体变更与 registry 鲜度治理

`EntityMutationChecklist` 必须逐类覆盖：

- 定义处
- 构造点 / factory
- 写入点 / repository / ORM
- 读取点 / query / selector
- 映射层 / mapper / adapter
- 序列化 / 反序列化 / validator
- API / DTO / event
- 测试 / fixture / mock / snapshot
- 前端消费
  - hook / store / page / widget / form / table / detail view
- 文档 / 示例

推荐结构：

```yaml
entity_mutation_checklist:
  entity_name: <string>
  categories:
    definition: <covered|gap>
    construction: <covered|gap>
    writes: <covered|gap>
    reads: <covered|gap>
    mapping: <covered|gap>
    serialization: <covered|gap>
    api_dto_event: <covered|gap>
    tests: <covered|gap>
    frontend_consumers: <covered|gap>
    docs_examples: <covered|gap>
  unresolved_categories:
    - <string>
```

规则：

- `EntityMutationChecklist` 是正式检查模板，不是结构名占位
- 若存在 `gap`，必须进入 `unresolved_categories` 或 blocker 判断

`RegistryFreshnessReport` 推荐结构：

```yaml
registry_freshness_report:
  object_path: <string>
  registry_consumers: <number>
  discovered_consumers: <number>
  freshness: <fresh|stale|unknown>
  divergence_summary: <string>
```

默认规则：

- registry 与 evidence 发现结果不一致时，默认按 discovered union 扩展
- 若 registry stale 且命中 `🔒` 对象，默认 `blocks-merge`

实体不可兼容冲突：

- `INCOMPATIBLE_MUTATION_CONFLICT`
  - 触发条件：
    - 实体 / DTO / event / API field 变更命中了某个 `🔒` consumer
    - 且没有兼容层、双字段、v2、mapper、adapter 等可行过渡路径
  - 默认 gate：
    - merge 阶段 `blocks-merge`
    - 若直接影响 release / ship compatibility baseline，则 ship gate 升级为 `blocks-ship`

## Public Errors / Gate Mapping

统一 error-code 清单：

- `IMPLICIT_SHARED_OBJECT_UNPROTECTED` -> `blocks-merge`，critical ship path 升级 `blocks-ship`
- `MIGRATION_PLAN_REQUIRED_BUT_MISSING` -> `blocks-merge`
- `MIGRATION_PLAN_INCOMPLETE` -> `blocks-merge`
- `MIGRATION_PHASE_ORDER_INVALID` -> `blocks-merge`
- `MIGRATION_RUNTIME_STATE_UNDECLARED` -> `blocks-merge`
- `LINKED_REGRESSION_EARLY_STOP` -> `blocks-merge`
- `LAYOUT_CONTRACT_BREAK` -> `blocks-merge`
- `BEHAVIOR_CONTRACT_BREAK` -> `blocks-merge`
- `INCOMPATIBLE_MUTATION_CONFLICT` -> `blocks-merge`，ship baseline 受影响时升级 `blocks-ship`

涉及迁移窗口 / removal precondition 的既有错误继续沿用：

- `COMPAT_WINDOW_VIOLATION`
- `COMPAT_REMOVAL_PRECONDITION_UNMET`

它们继续遵循：

- merge 阶段默认 `blocks-merge`
- ship / deploy gate 升级为 `blocks-ship`

- `v14` 单文件即可获得 `v12 + v13` 的完整规则，不需要再拼接补丁版
- `Public Interfaces / Contracts` 明确列出：
  - `MutationEligibilityAssessment`
  - `EntityMutationChecklist`
  - `LayoutContract`
  - `RegistryFreshnessReport`
  - `LinkedRegressionRecord`
  - `BehaviorContract`
  - `StagedMigrationPlan`
  - `migration_plan_requirement`
  - `implicit_shared_object_detection`
- 未登记对象命中 shared threshold 后生成 candidate，并在当前任务内立即按 `🟡 / 🔒` 生效
- 命中隐式共享对象后，既未回写也未阻断时，产出 `IMPLICIT_SHARED_OBJECT_UNPROTECTED`
- 同一 `regression_chain_id` 下连续 2 个 fix task 触发关联回归时，产出 `LINKED_REGRESSION_EARLY_STOP`
- layout contract 被破坏时，产出 `LAYOUT_CONTRACT_BREAK`
- behavior contract 被破坏时，产出 `BEHAVIOR_CONTRACT_BREAK`
- `recommend_task_split` 继续推进但无迁移计划时，产出 `MIGRATION_PLAN_REQUIRED_BUT_MISSING`
- `StagedMigrationPlan` 缺少 `runtime_state`，产出 `MIGRATION_RUNTIME_STATE_UNDECLARED`
- `StagedMigrationPlan` phase 不足、字段缺失、缺少 verification / exit criteria，产出 `MIGRATION_PLAN_INCOMPLETE`
- `EntityMutationChecklist` 必须按分类覆盖；存在 `gap` 时必须进入 unresolved 或 blocker 处理
- registry 与 evidence 结果不一致时，按 discovered union 扩展
- registry stale 且命中 `🔒` 对象时，触发 blocker
- 实体 / DTO / event / API field 命中 `🔒` consumer 且无兼容路径时，产出 `INCOMPATIBLE_MUTATION_CONFLICT`
- 所有上述错误结果都必须带：
  - `error_code`
  - `default_blocker_level`
  - `evidence`
  - `branch_gate_mapping`
  - `suggested_resolution`
