# vNext 公共入口内部恢复

状态：已实现共享执行器与入口接入，未运行测试或目标项目验证。
日期：2026-09-22。

## 执行关系

用户指令 → Skill 保存 invocation → run-entry 执行类型化操作 → 拒绝返回给 AI
复盘 → AI 选择恢复动作 → run-entry 执行恢复并接回原操作 → Skill 完成原职责。

`entry-runner.ts` 是可执行驱动，不是额外的状态数据库。原事务、finding、失败、
审查和用户决定仍由现有 Runtime 原子写入。每次驱动结果保留原操作、调用意图、
恢复动作及底层结果；跨调用依赖的 receipt 由 AI 读取后提交下一次驱动。
恢复请求不可原样无限重放，已完成的动作也不能重新当作未完成动作执行。

预算是 AI 分析点。普通重试预算由驱动根据具体尝试的复盘证据自动记录续行、
接回原操作；finding 与 repair-wave 通过现有扩额命令作为内部恢复动作执行。
用户原话和 AI 证据分开保留。没有把执行请求解释成风险接受或验证豁免。
驱动不负责自然语言判断，也不把一个内部操作成功冒充整个 Skill 已完成。

## 11 个入口的退出边界核对

| 入口 | 正常完成职责 | 应留在入口内部处理 | 需要用户或外部输入 |
|---|---|---|---|
| bootstrap-project | 当前模式的准备或治理事务及读回 | 过期准备、可恢复发布、请求修正 | 未确定的项目分类或所有权事实 |
| capture-work-item | 记录一项无关工作或确认重复 | 身份冲突、重复核对、事务恢复 | 无法判明的归属 |
| prepare-task | 当前模式的草案、确认或调整结果 | 过期候选、已有授权下的准备与提交 | 未确定的目标、范围、验收选择 |
| review-draft | 完成独立草案评审 | 上下文读取、失效引用修正 | 无法取得的审查材料 |
| execute-step | 本次步骤执行结果 | 诊断、preflight、审查消费、扩额、已授权调整、事务恢复 | 新业务选择或未授权范围 |
| review-change | 审查事实已记录 | context/receipt 修正、记录失败恢复 | 实际缺失且无法恢复的证据 |
| debug-task | 根因调查及有依据的处置路线 | 调查复盘、恢复证据读取、已授权内部准备 | 不可取得的复现条件或未确定的新选择 |
| close-task | 有依据的关闭与归档 | 决定绑定、义务核对、发布恢复 | 未决定的剩余风险处置 |
| task-lifecycle | 请求的生命周期转换 | 快照、包及原事务恢复 | 未确定的任务选择或冲突归属 |
| validate-change | 真实的验证证据或证据缺口结论 | 检查所需前提恢复、引用修正 | 无法内部提供的真实环境/证据 |
| git-commit | 授权范围内的提交结果 | 当前状态、候选文件和失败原因核对 | 未确定的提交范围或归属冲突 |

审查/调查/验证得到真实负面结论可以完成其职责；Runtime 拒绝记录该结论则仍需
内部恢复。跨入口共享内部能力不等于自动启动另一个公共 Skill。产品修改仍须
属于本次指令，不因恢复机制而擅自执行新的业务任务。

## 实现边界

所有入口模板接入 `run-entry`，源码契约检查要求驱动标记。CLI 转发原始错误码和
恢复路由；错误不再被一律描述成尚未执行。执行器只调已登记的本地 Runtime
命令，无 shell，不执行任意产品命令。现有低层 API 保留；绕过驱动的调用本身
不会自动获得恢复循环。用户指令真实性、AI 复盘质量和所有场景的有效性不能仅
凭结构检查或构建证明。本轮不将这些标记为已通过实际运行验证。


## 输出传输修订

子进程标准输出和错误直接落入独立临时回执文件，不再使用固定 16 MiB 缓冲上限。
默认返回摘要、outcome_ref 和 detail_ref；历史操作使用引用，不整包重复展开。
entry-output-read 按 UTF-8 边界分页并核对引用哈希。分页大小只限制一次读取，
不限制任务执行或恢复次数。临时回执不是任务事实源，遗失后应查原事务，不能
据此重复业务操作。内部 JSON 解析仍使用内存，本次没有宣称内部总开销恒定。
